6  Conditions and Loops

Audit rules are full of conditions. If the bill is above ₹50,000, it needs the sanction of a higher authority. If the work is not completed by the due date, liquidated damages are to be recovered. If a pensioner has not submitted a life certificate, the pension is to be stopped. And audit work is full of repetition. The same checks are run on the accounts of every district, and the same file is read for every month. In R, conditions are written with if and else, and repetition with loops.

So far our code has run line by line, from top to bottom. Control statements change this flow. if and else run some code only when a condition holds, and loops (for, while and repeat) run some code again and again. Together with functions (Chapter 3), they let us automate any task.

In data analysis we need them less than in other programming, because R’s functions work on whole vectors at once, and the tidyverse handles most repetition for us. Still, they are core concepts of any programming language, and are needed often enough, for example to process a folder of files one by one, or inside our own functions.

6.1 Control flow and loops

if else

The basic forms of the if else statement in R are these.

if (test) do_this_if_true
if (test) do_this_if_true else else_do_this

So, if test is TRUE, do_this_if_true is run, and, optionally, if it is FALSE, else_do_this is run. See this example.

x <- 50
if(x < 10){
  'Smaller than 10'
} else {
  '10 or more'
}
[1] "10 or more"

The same pattern answers a simple audit question about one bill.

bill_amount <- 62000
if (bill_amount > 50000) {
  'Check the sanction of the higher authority'
} else {
  'Within the powers of the drawing officer'
}
[1] "Check the sanction of the higher authority"

Several conditions can be chained with else if. They are checked in order, and the first one which is TRUE decides. Let us write a function which tells the authority competent to sanction an expenditure, under some made-up financial powers.

sanctioning_authority <- function(amount) {
  if (amount <= 50000) {
    "Section Officer"
  } else if (amount <= 500000) {
    "Deputy Secretary"
  } else if (amount <= 2500000) {
    "Joint Secretary"
  } else {
    "Secretary"
  }
}
sanctioning_authority(42000)
[1] "Section Officer"
sanctioning_authority(1800000)
[1] "Joint Secretary"
TipAudit tip

Look hard at the limits. The function uses <=, so an amount of exactly ₹50,000 goes to the Section Officer. Read the actual delegation order. If it says “below ₹50,000”, the test must be < instead. Test the function with amounts exactly on each limit, and one rupee on either side.

WarningCaution

if checks a single TRUE or FALSE. Unlike the function ifelse(), it is not vectorised. Given a vector of conditions, it stops with an error (since R 4.2). And given NA, it stops too, since it cannot decide which way to go.

if (c(10, 60) > 50) "large"
Error in `if (c(10, 60) > 50) ...`:
! the condition has length > 1
if (NA > 50) "large"
Error in `if (NA > 50) ...`:
! missing value where TRUE/FALSE needed

To combine conditions in if, use && and ||, which work on single values. To guard against NA, wrap the condition in isTRUE(), which is TRUE only for a single TRUE. And to apply the function above to a whole vector of amounts, use sapply() or purrr::map_chr(), which we will learn in Section 7.5, or better, the vectorised dplyr::case_when().

switch()

When the choice depends on a single value, switch() is neater than a long chain of else if.

fund_name <- function(code) {
  switch(code,
         CFI = "Consolidated Fund of India",
         CON = "Contingency Fund",
         PA  = "Public Account",
         "Unknown code")   # the last, unnamed value is the default
}
fund_name("PA")
[1] "Public Account"
fund_name("XYZ")
[1] "Unknown code"

for loop

A for loop runs some code once for each item of a vector. The basic structure is this.

for(item in vector) perform_some_action

# OR

for(item in vector) {
  perform_some_action
}

For each item in vector, perform_some_action is run once, with item taking the next value each time. See this simple example.

for(i in 1:3){
  print(i)
}
[1] 1
[1] 2
[1] 3

By convention, i is used for the item, but any name may be used.

for(item in 1:3){
  print(item)
}
[1] 1
[1] 2
[1] 3

The for loop creates the item in the current environment, overwriting any existing object with the same name. See this example.

x <- 500
for(x in 1:3){
  # do nothing
}
x
[1] 3

We can loop over positions, to work with as many elements as we want. See these two examples. The first loops over the first four offices only.

my_offices <- c('DTO Ajmer', 'DTO Alwar', 'DTO Bikaner', 'DTO Jaipur', 'DTO Kota')
# If we want first 4 elements
for(i in 1:4){
  print(my_offices[i])
}
[1] "DTO Ajmer"
[1] "DTO Alwar"
[1] "DTO Bikaner"
[1] "DTO Jaipur"

The second loops over all of them.

# if we want all elements
for(i in seq_along(my_offices)){
  print(my_offices[i])
}
[1] "DTO Ajmer"
[1] "DTO Alwar"
[1] "DTO Bikaner"
[1] "DTO Jaipur"
[1] "DTO Kota"

Storing the results. A loop which only prints is of limited use. Usually we store each result. Create an empty vector of the right length before the loop, and fill it in. Growing a vector inside a loop, with c(), works but becomes very slow for long loops.

amounts <- c(42000, 1800000, 260000, 9000000)
authority <- character(length(amounts))   # empty vector, filled in below
for (i in seq_along(amounts)) {
  authority[i] <- sanctioning_authority(amounts[i])
}
authority
[1] "Section Officer"  "Joint Secretary"  "Deputy Secretary" "Secretary"

There are two ways to end an iteration, or the loop, early.

  • next skips the rest of the current iteration, and moves to the next item.
  • break ends the entire loop.

See these examples. With next, the loop skips the fourth item and carries on.

for(i in 1:5){
  if (i == 4){
    next
  }
  print(i)
}
[1] 1
[1] 2
[1] 3
[1] 5

With break, the loop stops at the fourth item.

for(i in 1:5){
  if (i == 4){
    break
  }
  print(i)
}
[1] 1
[1] 2
[1] 3

In audit, next is handy to skip records that should not be checked, like cancelled vouchers.

voucher <- c("V-101", "V-102", "V-103", "V-104")
status  <- c("Paid", "Cancelled", "Paid", "Paid")
for (i in seq_along(voucher)) {
  if (status[i] == "Cancelled") next
  print(paste("Checking", voucher[i]))
}
[1] "Checking V-101"
[1] "Checking V-103"
[1] "Checking V-104"

while loop

A for loop runs over known values, a known number of times. To repeat something an unknown number of times, we use a while loop, which repeats as long as a condition is TRUE. Another option is the repeat loop, which repeats until it meets a break.

The basic syntax of the while loop is this.

while (condition) action

See these examples. The first counts up.

i <- 1
while(i <=4){
  print(LETTERS[i])
  i <- i+1
}
[1] "A"
[1] "B"
[1] "C"
[1] "D"

We may check the value of i after the loop has run.

i
[1] 5

The second counts down.

i <- 4
while(i >= 1){
  print(LETTERS[i])
  i <- i-1
}
[1] "D"
[1] "C"
[1] "B"
[1] "A"

The code inside the loop must change something in the condition, so that sooner or later it is no longer TRUE. Otherwise the loop never ends. If that happens, press Esc in RStudio to stop it.

Here is a while loop with a real use. How many years will a deposit of ₹10 lakh at 7% compound interest take to double? An auditor may ask this when checking the maturity value claimed for a fixed deposit of idle scheme funds.

balance <- 1000000
years <- 0
while (balance < 2000000) {
  balance <- balance * 1.07
  years <- years + 1
}
years
[1] 11

The same can be written with repeat and break.

balance <- 1000000
years <- 0
repeat {
  balance <- balance * 1.07
  years <- years + 1
  if (balance >= 2000000) break
}
years
[1] 11
NoteLoops or vectors?

Before writing a loop over the rows of a table, check whether a vectorised function can do the job, as it usually can. amounts * 1.18 adds GST to every amount at once, and ifelse() or dplyr::case_when() classify every row at once. Such code is shorter, clearer, and much faster on large data. Where repetition is really needed, like reading many files, the functions of the apply family and of purrr, discussed in Chapter 7, are usually neater than a loop. Loops are not wrong, though. A clear loop is better than clever code you cannot check.

6.2 A suggested workflow

  1. Look for a vectorised way first. Before writing a loop over rows, check whether ifelse() or dplyr::case_when() can do the job on the whole column at once.
  2. Write the rule for one value. Express the decision with if, else if and else, or with switch() when the choice depends on a single code.
  3. Guard against NA. Use &&, || and isTRUE() so that a missing value does not stop the code.
  4. Test the rule on a few known values. Try amounts just below and just above each limit. Check that the answer is what the rules say.
  5. Prepare storage before looping. Create an empty vector of the right length with character() or numeric(), and loop over seq_along().
  6. Use next and break with care. Skip items that should not be processed, and stop early only when the job is truly done.
  7. Make sure a while loop can end. The code inside must change the condition. If it runs forever, press Esc in RStudio.
ImportantRemember

if checks a single TRUE or FALSE, not a whole column. For a column of amounts, use a vectorised function. A clear loop is still better than clever code you cannot check.
