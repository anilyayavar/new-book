26  Probability Distributions

An auditor tests a sample of 60 vouchers for a missing sanction and finds none. Can we now say the control works? Or were we simply lucky? A toll plaza reports a day’s receipts far below its usual level. Is that day merely unusual, or is it worth a question? Both are questions of probability. Every statistical sampling plan, and every judgement that a figure is “too far from normal”, rests on a probability distribution.

We will keep this chapter short. Instead of learning all the concepts of probability, we will see how to calculate probabilities, densities, quantiles and random numbers for nearly any distribution. Base R has four functions for each common distribution. Their names start with the prefixes p, q, d and r, followed by a short name of the distribution, like norm for the normal distribution or binom for the binomial.

All these functions are vectorised. Let us explore them one by one, and then use them on the two questions of sampling that every auditor meets.

26.1 p*() set of functions

These functions give the cumulative probability, that is, the probability that a value is less than or equal to a given number.

Suppose the daily receipts at a toll plaza follow a normal distribution, with a mean of ₹50 thousand and a standard deviation of ₹10 thousand. What is the probability of a day with receipts of ₹25 thousand or less?

pnorm(25, mean = 50, sd = 10)
[1] 0.006209665

The chance is about 0.62%, less than one day in a hundred. A day with such low receipts is unusual enough to ask the plaza for the reason.

On the other hand, the probability of receipts above ₹25 thousand on a day is found in either of two ways.

# Either deduct probability from 1
1 - pnorm(25, mean = 50, sd = 10)
[1] 0.9937903
# Or provide FALSE to lower.tail argument
pnorm(25, mean = 50, sd = 10, lower.tail = FALSE)
[1] 0.9937903

Now a discrete example. What is the probability of getting one or more heads in two tosses of a fair coin? The number of heads follows a binomial distribution with size = 2 and prob = 0.5. “One or more” is the same as “more than zero”, so we ask for the upper tail above 0.

pbinom(0, size = 2, prob = 0.5, lower.tail = FALSE)
[1] 0.75
WarningCaution

Be careful with discrete distributions. pbinom(1, ...) would give the probability of at most one head, which is a different question. Here it happens to give the same number, 0.75, by coincidence of this small example, but in general the two differ.

26.2 q*() set of functions

These functions give the quantile, which is the inverse of the cumulative probability. If \(F\) is the cumulative distribution function, which turns a value \(x\) into a probability \(p\), then the quantile function \(F^{-1}\) turns a probability back into a value.

\[ p = F(x) \tag{26.1}\]

\[ x = F^{-1}(p) \tag{26.2}\]

For the same toll plaza (mean = 50 and sd = 10, in ₹ thousand), below which value do the receipts of 90% of the days lie?

qnorm(0.9, mean = 50, sd = 10)
[1] 62.81552

So on nine days out of ten, the receipts should be below about ₹62.8 thousand.

As with the p functions, we may use the lower.tail argument to find the value above which 90% of the values lie.

qnorm(0.9, mean = 50, sd = 10, lower.tail = FALSE)
[1] 37.18448

Receipts below about ₹37.2 thousand happen on only one day in ten.

26.3 d*() set of functions

The p functions give cumulative probabilities and the q functions their inverse. The d functions give the density, the height of the distribution at a given value. For a discrete distribution like the binomial, this height is simply the probability of exactly that value.

So what is the probability of getting exactly 2 heads in two tosses of a fair coin?

dbinom(2, size = 2, prob = 0.5)
[1] 0.25

For a continuous distribution like the normal, the density is not a probability itself. Probabilities come from areas under the curve, which the p functions give.

26.4 r*() set of functions

These functions generate random numbers from a distribution. So to generate 10 random numbers from a normal distribution with mean = 50 and sd = 10, we use rnorm(). Setting a seed with set.seed() makes the result reproducible.

set.seed(2024)
rnorm(10, mean = 50, sd = 10)
 [1] 59.81969 54.68715 48.92029 47.87122 61.58098 62.92355 55.34647 48.72965
 [9] 37.75125 38.78649

We can check the shape of the distribution with a histogram of many such numbers (Figure 26.1).

set.seed(1234)
hist(rnorm(10000, 50, 10), breaks = 50, main = NULL, xlab = "Value")

The r functions are how we create the simulated data used throughout this book, like the payments and claims with planted irregularities.

26.5 Audit use case, probability in audit sampling

Why should an auditor care about these functions? Because every statistical sample rests on them. Let us see two questions that come up in every sampling plan.

Question 1. If I find no errors in my sample, how sure can I be? Suppose the true rate of deviations from a control is 5%, which we would consider too high. We test 60 items and find none. What is the chance of that happening? Each item is a deviation with probability 0.05, so the number of deviations in 60 items follows a binomial distribution.

dbinom(0, size = 60, prob = 0.05)
[1] 0.0460698

There is only a 4.6% chance of finding no deviation in 60 items if the true rate were 5%. So if we do find none, we can be about 95% confident that the true rate is below 5%. This is the logic behind sample sizes for tests of controls.

TipAudit tip

Decide the rate you would consider too high, and the confidence you need, before testing the sample. Record both in the working papers. A conclusion is weaker if these are chosen after seeing the results.

For small rates and large populations, the Poisson distribution gives nearly the same answer, with only one parameter, the expected number of deviations, here \(60 \times 0.05 = 3\).

ppois(0, lambda = 3)
[1] 0.04978707

Question 2. What is the highest rate consistent with what I found? The Poisson distribution also tells us how high the true number of errors could be, at a chosen confidence level, given the errors we found. These upper limits are called reliability factors or confidence factors, and auditors usually read them from printed tables. In R they come from a single function, qgamma(), because of a mathematical link between the Poisson and gamma distributions.

# Reliability factors for 0 to 5 errors found
tibble::tibble(errors_found = 0:5,
               factor_95    = round(qgamma(0.95, 0:5 + 1), 2),
               factor_90    = round(qgamma(0.90, 0:5 + 1), 2))
# A tibble: 6 × 3
  errors_found factor_95 factor_90
         <int>     <dbl>     <dbl>
1            0      3         2.3 
2            1      4.74      3.89
3            2      6.3       5.32
4            3      7.75      6.68
5            4      9.15      7.99
6            5     10.5       9.27

These are exactly the factors printed in audit sampling tables. The factor 3.00 for zero errors at 95% confidence is the most used number in audit sampling. It gives the familiar rule of thumb. If a sample of \(n\) items has no errors, we can be 95% confident that the error rate is below \(3/n\). For 60 items, that is 5%. We will use these factors to calculate sample sizes and evaluate results in the next chapter, Chapter 27.

NoteWhy does qgamma() give Poisson limits?

If errors occur at random, at an average of \(\lambda\) per sample, then the probability of seeing \(k\) or fewer errors is ppois(k, lambda). The upper limit at 95% is the value of \(\lambda\) for which this probability falls to 5%. That value happens to be the 95th percentile of a gamma distribution with shape \(k + 1\), so qgamma(0.95, k + 1) gives it directly. We can check it.

ppois(0, qgamma(0.95, 1))
[1] 0.05
ppois(2, qgamma(0.95, 3))
[1] 0.05

26.6 A suggested workflow

  1. Know the question. Decide whether you need the chance of at most a value, more than a value, or exactly a value. Each needs a different function or argument.
  2. Choose the distribution. The number of deviations in a sample of vouchers follows the binomial distribution. For small rates and large populations, the Poisson distribution gives nearly the same answer, with one parameter.
  3. Use the right function. Use pbinom() or ppois() for cumulative probability, with lower.tail = FALSE for the upper tail. Use dbinom() for exactly a value, and a q function for the value below which a given share lies.
  4. Test what “no errors” means. Before concluding that a control works, use dbinom() to find the chance of seeing no deviation in your sample if the true rate were too high.
  5. Get reliability factors in R. Calculate the factors for the number of errors found with qgamma(), instead of reading them from printed tables. They are used for sample sizes and evaluation in the next chapter.
  6. Make simulations reproducible. When you generate test data with rnorm() or another r function, call set.seed() first. A reviewer can then get the same numbers.
ImportantRemember

For a count, at most one and one or more are different questions. Check which tail you need before using a p function. A wrong tail gives a wrong level of assurance in the sampling conclusion.
