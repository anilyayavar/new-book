7  Functional Programming

A Public Works department has dozens of divisions. Each sends its voucher file every month. The auditor wants to run the same checks on every file. What did the division spend? How much of it was spent in March? Which vouchers are above the limit? Doing this by hand, file by file, is slow. Copying the code for each file and editing it is quicker, but risky. One forgotten edit, and one division is checked against the wrong limit, without anyone noticing.

The better way is to write the check once, as a function, and then tell R to apply it to every file. This idea, applying a function to each element of a collection, is the heart of functional programming. R is very good at it.

In this chapter we learn the base R tools for this, the apply family, and then the more consistent tools of the package purrr. We practise on the voucher register of four sub-division offices, and on its quarter-wise expenditure. At the end, we check every office for a rush of expenditure in March, with one function applied to all four.

7.1 What is functional programming?

Conceptually functional programming philosophy is based on lambda calculus. Lambda calculus is a framework developed by Alonzo Church1 to study computations with functions.

Functional programming is a style of programming built around functions, in the mathematical sense. It is declarative. Its focus is on what to solve, in contrast to the imperative style, like a for loop, whose focus is on how to solve. For a fuller definition, readers may see this Wikipedia link. Put simply, instead of writing a loop which says “take the first element, do this, store the result, take the next element…”, we say “apply this function to every element”, and let R do the rest.

Functional programming uses higher-order functions, functions which take another function as an argument, or return a function. We have already seen one, perhaps without noticing. args() takes a function as its argument, and returns its arguments.

Let us learn a bit more here.

7.2 Our data, vouchers of four offices

Our data is the voucher register of a Public Works division for the financial year 2024-25. It has four sub-division offices, at Pune, Nashik, Nagpur and Kolhapur. Each row is one voucher, with its office, date, amount and the GST in it. One office has a rush of large payments in the last fortnight of March, which we find at the end of the chapter. From the vouchers we also make a small matrix, qexp, of the expenditure of each office in each quarter, in lakh. All names are made up, and the code is folded.

Code to create the vouchers and the quarter-wise expenditure
set.seed(7)
offices <- c("Pune", "Nashik", "Nagpur", "Kolhapur")
n <- 160
vouchers <- data.frame(
  office       = sample(offices, n, replace = TRUE),
  voucher_date = as.Date("2024-04-01") + sample(0:364, n, replace = TRUE),
  amount       = round(runif(n, 20000, 200000), -2)
)

# Planted. A rush of large payments at Nagpur in the second half of March 2025
march_rush <- data.frame(
  office       = "Nagpur",
  voucher_date = as.Date("2025-03-17") + c(0, 3, 5, 8, 10, 12, 13),
  amount       = c(480000, 520000, 450000, 610000, 395000, 560000, 470000)
)

vouchers <- rbind(vouchers, march_rush)
vouchers <- vouchers[order(vouchers$voucher_date), ]
vouchers$voucher_no <- sprintf("TV/24-25/%03d", seq_len(nrow(vouchers)))
vouchers$gst <- round(vouchers$amount * 18 / 118)
vouchers <- vouchers[, c("voucher_no", "office", "voucher_date", "amount", "gst")]
rownames(vouchers) <- NULL

# Quarter of the financial year. April to June is Q1, January to March is Q4
quarter <- paste0("Q", (as.integer(format(vouchers$voucher_date, "%m")) - 4) %% 12 %/% 3 + 1)
# Expenditure of each office in each quarter, in lakh
qexp <- round(tapply(vouchers$amount, list(vouchers$office, quarter), sum) / 1e5, 2)

7.2.1 Usage of functional programming in R

Strictly speaking, R is not a pure functional programming language, but it supports the style well. We have seen that most functions work on whole vectors at once. But what about lists? Many functions do not work on them. Suppose three amounts have been kept in a list. Check this example.

list1 <- list(50000, 5000, 56)
sum(list1)
Error in `sum()`:
! invalid 'type' (list) of argument

Of course, we can solve the above problem with a for loop. See

list1 <- list(50000, 5000, 56)
# for loop strategy
x <- c()
for(i in seq_along(list1)){
  x[i] <- list1[[i]]
}
sum(x)
[1] 55056

Consider another list, the bills passed by three offices in one week, where we want the average bill of each office.

office_bills <- list(
  Pune   = c(42000, 18500, 61000, 27500),
  Nashik = c(99500, 98000, 99900),
  Nagpur = c(12500, 230000, 45000, 8800, 76000)
)

We may use a for loop again, but in R such operations are done more simply with the apply family of functions, one of the best known features of R. We will come back to office_bills shortly.

7.3 apply family of functions

The first of these functions is apply(), which works on matrices and data frames.

7.3.1 Function apply()

The basic syntax of apply is

apply(m, MARGIN, FUN, f_args)

where

  • m is the matrix
  • MARGIN is the dimension. To apply the function to each row, use 1, and to each column, 2
  • FUN is the function to apply
  • f_args are any further arguments to be passed to FUN.

An illustrative construction of apply function can be seen in Figure 7.1.

Let us find the average quarterly expenditure of each office, from our matrix qexp. Each row is an office, so MARGIN is 1.

apply(qexp, 1, mean)
Kolhapur   Nagpur   Nashik     Pune 
 14.3800  18.5500   9.5400   7.5875

Note: rowMeans(qexp) would have given the same result. We use a simple example to show the idea.

We may also pass our own function. Government instructions discourage a rush of expenditure at the end of the year. A common yardstick is that not more than a third, 33%, of the year’s spending should fall in the last quarter. Let us write a function which gives the share of the last quarter, Q4, in a row, and then apply it to every office.

q4_share <- function(x){
  round(x[4] / sum(x) * 100, 1)
}
apply(qexp, 1, q4_share)
Kolhapur   Nagpur   Nashik     Pune 
    24.4     54.6     21.6     27.6

Nagpur spent 54.6% of its year’s money in the last quarter. The other offices are within the yardstick.

If the function is not needed elsewhere, there is no need to define it beforehand. We may write an anonymous function directly inside apply().

apply(qexp, 1, FUN = function(x) round(x[4] / sum(x) * 100, 1))
Kolhapur   Nagpur   Nashik     Pune 
    24.4     54.6     21.6     27.6
Note

Since R 4.1, a function can be written with a backslash \ in place of the word function (see Chapter 3). We could have written the above as

apply(qexp, 1, FUN = \(x) round(x[4] / sum(x) * 100, 1))
## Kolhapur   Nagpur   Nashik     Pune 
##     24.4     54.6     21.6     27.6

apply() need not necessarily output vectors only

If FUN returns more than one value for each row or column, the output is a matrix. The thing to note is that the result for each row or column is always placed in a column of the output, whether MARGIN is 1 or 2. (A function like sqrt would not show this well, since apply(m, 1, sqrt) gives the same values as sqrt(m).)

Suppose we want the progressive expenditure of each office, that is, its running total at the end of each quarter. The running total is given by cumsum(). First, let us do it on each column, with MARGIN = 2.

apply(qexp, 2, cumsum)
            Q1    Q2    Q3    Q4
Kolhapur  8.19 19.80 15.51 14.02
Nagpur   19.10 30.66 27.43 54.53
Nashik   25.86 41.20 40.05 62.77
Pune     31.80 48.36 48.91 71.16

The layout is the same as that of qexp. But a running total down a column adds up the offices, which means nothing to us. We want the running total along each row, over the quarters.

apply(qexp, 1, cumsum)
   Kolhapur Nagpur Nashik  Pune
Q1     8.19  10.91   6.76  5.94
Q2    27.99  21.77  17.30 13.10
Q3    43.50  33.69  29.92 21.96
Q4    57.52  74.20  38.16 30.35

The numbers are right, but the output is the transpose of what we expected. The offices are now columns, because the result for each row has gone into a column. Wrap it in t() to get the expected layout.

t(apply(qexp, 1, cumsum))
            Q1    Q2    Q3    Q4
Kolhapur  8.19 27.99 43.50 57.52
Nagpur   10.91 21.77 33.69 74.20
Nashik    6.76 17.30 29.92 38.16
Pune      5.94 13.10 21.96 30.35

Let us check our understanding with one more example, using a function whose output length does not depend on the input. range() always gives two values, the smallest and the largest.

apply(qexp, 1, range)
     Kolhapur Nagpur Nashik Pune
[1,]     8.19  10.86   6.76 5.94
[2,]    19.80  40.51  12.62 8.86

Thus we may conclude that

  • if FUN returns a single value, the output of apply is a vector whose length is
    • the number of rows of the input, if MARGIN is 1,
    • the number of columns of the input, if MARGIN is 2;
  • if FUN returns a vector of length more than 1, the output is a matrix whose number of columns is
    • the number of rows of the input, if MARGIN is 1,
    • the number of columns of the input, if MARGIN is 2.

These have been tabulated in Table 7.1.

So we have to be careful with the output of apply(), or it may introduce a bug in our code.

apply() on data frames

Data frames, though a kind of list, also behave like matrices, so we may use apply() on them too. Let us turn qexp into a data frame, and total each quarter.

(qexp_df <- as.data.frame(qexp))
            Q1    Q2    Q3    Q4
Kolhapur  8.19 19.80 15.51 14.02
Nagpur   10.91 10.86 11.92 40.51
Nashik    6.76 10.54 12.62  8.24
Pune      5.94  7.16  8.86  8.39
apply(qexp_df, 2, sum)
   Q1    Q2    Q3    Q4 
31.80 48.36 48.91 71.16
WarningCaution

apply() first converts a data frame into a matrix. If the data frame has even one text column, every value becomes text, and numeric functions fail or give wrong results. See what happens when we try to add GST to each amount, row by row, while the voucher number is also in the data.

small <- vouchers[1:4, c("voucher_no", "amount")]
apply(small, 1, \(r) r["amount"] * 1.18)
Error in `r["amount"] * 1.18`:
! non-numeric argument to binary operator

The amounts had become text, and text cannot be multiplied. Use apply() only on all-numeric data, and prefer lapply(), sapply() or, in the tidyverse, across() (Section 13.15) for data frames.

7.3.2 Function lapply()

lapply() is the cousin of apply() for lists, as its name suggests. Since a data frame is also a list, lapply() works on data frames too, column by column. The basic syntax of lapply() is

lapply(l, FUN, f_args)

where

  • l is the list
  • FUN is the function to apply
  • f_args are any further arguments to be passed to FUN.

Note that there is no MARGIN argument here. Let us total each quarter again, this time with lapply().

lapply(qexp_df, sum)
$Q1
[1] 31.8

$Q2
[1] 48.36

$Q3
[1] 48.91

$Q4
[1] 71.16

You may have noticed two things here.

  1. The output is a list.
  2. FUN is applied to every element of the list. Each column of a data frame is an element, so lapply() works column by column, never row by row.

Thus lapply()

  • loops over a list, iterating over each element in that list
  • then applies the function FUN to each element
  • and then returns a list.

The first thing to check in any file received from an auditee is the type of each column. Is the date really a date? Is the amount a number, or text? lapply() with class() tells us at once.

lapply(vouchers, class)
$voucher_no
[1] "character"

$office
[1] "character"

$voucher_date
[1] "Date"

$amount
[1] "numeric"

$gst
[1] "numeric"

As with apply(), we can write FUN inline (anonymously). This gives the share of each office in each quarter’s expenditure, in per cent.

lapply(qexp_df, \(a) round(a / sum(a) * 100, 1))
$Q1
[1] 25.8 34.3 21.3 18.7

$Q2
[1] 40.9 22.5 21.8 14.8

$Q3
[1] 31.7 24.4 25.8 18.1

$Q4
[1] 19.7 56.9 11.6 11.8

The element of the list goes to the first argument of FUN which is not already named. Suppose we want to pick 3, 2 and 4 voucher numbers at random from the range 1001 to 1050, for three audit teams. sample() takes the values to pick from as x, and the number to pick as size. Since we have named x, each number goes to size.

set.seed(1)
lapply(c(3, 2, 4), sample, x = 1001:1050)
[[1]]
[1] 1004 1039 1001

[[2]]
[1] 1034 1023

[[3]]
[1] 1043 1014 1018 1033

Note that even when lapply() is applied to a vector, it returns a list.

And now office_bills, from the beginning of the chapter. The average bill of each office is simply

lapply(office_bills, mean)
$Pune
[1] 37250

$Nashik
[1] 99133.33

$Nagpur
[1] 74460

7.3.3 Function sapply()

sapply() is a simplified lapply(). It works the same way, but simplifies the result as much as possible, usually into a vector or a matrix.

sapply(qexp_df, sum)
   Q1    Q2    Q3    Q4 
31.80 48.36 48.91 71.16 
sapply(office_bills, mean)
    Pune   Nashik   Nagpur 
37250.00 99133.33 74460.00
WarningCaution

The convenience has a cost. What sapply() returns depends on the data, a vector one day and a list another, which can break code silently. For code that will be reused, prefer vapply(), described below, or the purrr functions.

7.4 Other loop functions

7.4.1 Function replicate()

replicate() evaluates an expression repeatedly. It is mostly used in simulations. The syntax is

replicate(n, expr, simplify = "array")

where

  • n is the number of replications
  • expr is the expression to evaluate repeatedly
  • simplify says whether the results should be simplified into a vector, matrix or array.

Suppose we draw a random sample of 10 vouchers, and work out their average amount. How much would that average change from one sample to another? replicate() draws five such samples, and gives the five averages. Then, with simplify = FALSE, it draws three samples of four voucher numbers each, and keeps each sample as an element of a list.

set.seed(123)
# Default value of simplify will simplify the results as much possible
replicate(5, mean(sample(vouchers$amount, 10)))
[1] 128070 104530  95220 196320 108110
# Notice the difference with simplify=FALSE
replicate(3, sample(vouchers$voucher_no, 4), simplify = FALSE)
[[1]]
[1] "TV/24-25/016" "TV/24-25/116" "TV/24-25/094" "TV/24-25/006"

[[2]]
[1] "TV/24-25/086" "TV/24-25/167" "TV/24-25/039" "TV/24-25/159"

[[3]]
[1] "TV/24-25/118" "TV/24-25/050" "TV/24-25/034" "TV/24-25/004"

Audit sampling itself is the subject of Chapter 27.

7.4.2 Function split()

split() divides an object (a vector, list or data frame) into groups, given by a factor. The result is a list, with one element for each group. The basic syntax is

split(x, f, drop=FALSE, ...)

where

  • x is the object to split, a vector, list or data.frame
  • f is a factor, or a list of factors. Anything else is converted to a factor.
  • drop says whether groups with no data should be dropped.

For example, to share the first ten vouchers between two audit teams, alternately,

split(vouchers$voucher_no[1:10], rep(c("Team A", "Team B"), 5))
$`Team A`
[1] "TV/24-25/001" "TV/24-25/003" "TV/24-25/005" "TV/24-25/007" "TV/24-25/009"

$`Team B`
[1] "TV/24-25/002" "TV/24-25/004" "TV/24-25/006" "TV/24-25/008" "TV/24-25/010"

The total expenditure of each office,

split(vouchers$amount, vouchers$office) |> lapply(sum)
$Kolhapur
[1] 5752500

$Nagpur
[1] 7421100

$Nashik
[1] 3816100

$Pune
[1] 3035400

And the largest voucher of each office,

split(vouchers$amount, vouchers$office) |> sapply(max)
Kolhapur   Nagpur   Nashik     Pune 
  196100   610000   199500   194800

7.4.3 tapply()

tapply() combines split() and sapply() for vectors, exactly as in the last example. It applies a function to each group of a vector. The basic syntax is

tapply(X, INDEX, FUN = NULL, ..., default = NA, simplify = TRUE)

where

  • X is a vector
  • INDEX is a factor, or a list of factors, giving the groups
  • FUN is the function to apply
  • ... are any further arguments for FUN
  • simplify, if TRUE, simplifies the result.

The largest voucher of each office again, in one step.

tapply(vouchers$amount, vouchers$office, max)
Kolhapur   Nagpur   Nashik     Pune 
  196100   610000   199500   194800

If simplify is FALSE, the results are not simplified. See this example, the average voucher of each office.

tapply(vouchers$amount, vouchers$office, mean, simplify = FALSE)
$Kolhapur
[1] 112794.1

$Nagpur
[1] 172583.7

$Nashik
[1] 90859.52

$Pune
[1] 97916.13

With a list of two factors as INDEX, tapply() gives a cross-table. This is how the matrix qexp was made from the vouchers, with the office and the quarter as the two factors.

7.4.5 Specifying the output type with vapply()

vapply() works like sapply(), except that we must state the type and length of each result, in the argument FUN.VALUE. If a result does not match, it stops with an error, instead of returning something unexpected. Its syntax is

vapply(X, FUN, FUN.VALUE, ..., USE.NAMES = TRUE)
  • In the argument FUN.VALUE we give a template of each result. See this example, the largest amount and the largest GST.
vapply(vouchers[c("amount", "gst")], max, FUN.VALUE = double(1))
amount    gst 
610000  93051

With FUN.VALUE = double(1) we have said that each result should be a single double. To find the range of each column, which has two values,

vapply(vouchers[c("amount", "gst")], range, FUN.VALUE = double(2))
     amount   gst
[1,]  20300  3097
[2,] 610000 93051

If we try this on the whole register, which has text columns like the voucher number and the office, vapply() stops with an error, as we want it to.

vapply(vouchers, range, FUN.VALUE = double(2))
Error in `vapply()`:
! values must be type 'double',
 but FUN(X[[1]]) result is type 'character'

7.5 Functional Programming in purrr

The package purrr2, part of the core tidyverse, gives a complete and consistent set of tools for functional programming. Its functions do the job of the apply family, with consistent names and arguments, and a guaranteed type of output.

library(purrr)

7.5.1 Iterate over single list/vector with map_*() family of functions

The most important family of functions in purrr is map. The map_*() functions work much like vapply(), with control over the type of output. They all take a list or vector as the argument .x and a function as .f, and return an output of the stated type.

Let us total each quarter of qexp_df once more.

map(qexp_df, .f = sum)
$Q1
[1] 31.8

$Q2
[1] 48.36

$Q3
[1] 48.91

$Q4
[1] 71.16

Note that the output is a list, just as with lapply(). If each result is a single value, we use one of these functions, depending on its type, to get a vector.

  • map_lgl for logical format
  • map_int for integer format
  • map_dbl for double format
  • map_chr for character format. Since purrr version 1.2, map_chr() no longer converts numbers or logical values into text automatically. If the function returns numbers, use map_dbl(), or convert the result explicitly with as.character().

map() always returns a list. See these further examples.

The largest amount and the largest GST, as a vector of doubles.

map_dbl(vouchers[c("amount", "gst")], max)
amount    gst 
610000  93051

An anonymous function, written with \(x). (Older code often uses a formula instead, like ~ mean(.x). It still works, but \(x) is now recommended.) The first line gives the average bill of each office. The second turns month numbers into names.

map_dbl(office_bills, \(x) mean(x))
    Pune   Nashik   Nagpur

7.5.2 Iterate over two or more lists/vectors using map2_*()/ pmap_*() family

So far, map_*() has iterated over the elements of one list. Any extra arguments are passed unchanged, the same in every iteration, as in the first illustration in Figure 7.23.

To iterate over two vectors or lists together, taking their elements in pairs, we need the map2_*() family of functions (see the second illustration in Figure 7.2).

See the following example. Each office has its own limit for a single bill, and map2() takes the bills of each office together with its own limit.

office_limits <- c(Pune = 50000, Nashik = 100000, Nagpur = 100000)
map2(office_bills, office_limits, \(x, lim) x[x > lim])
$Pune
[1] 61000

$Nashik
numeric(0)

$Nagpur
[1] 230000

Pune has one bill above its limit, and Nagpur has one above its own. Nashik has none. Its three bills are all a little below ₹1 lakh, which is itself worth a second look (Section 13.17).

Here is another audit use. Claims under three schemes are to be checked against each scheme’s own limit. map2() takes each scheme’s claims together with its limit.

claims <- list(Health    = c(12000, 155000, 8000, 140000),
               Education = c(30000, 9000, 61000),
               Housing   = c(150000, 260000, 90000))
limits <- c(Health = 100000, Education = 50000, Housing = 250000)

map2(claims, limits, \(x, lim) x[x > lim])      # the claims above the limit
$Health
[1] 155000 140000

$Education
[1] 61000

$Housing
[1] 260000
map2_int(claims, limits, \(x, lim) sum(x > lim)) # how many
   Health Education   Housing 
        2         1         1

Another use is a completeness check. From the first and last numbers of each cheque book issued, map2() builds the full list of cheque leaves, which can then be compared with the cheques accounted for.

cheque_books <- data.frame(first = c(500101, 500126), last = c(500125, 500150))
all_leaves <- map2(cheque_books$first, cheque_books$last, seq) |> unlist()
length(all_leaves)
[1] 50
accounted <- c(500101:500118, 500120:500150)   # say, from the cheque register
setdiff(all_leaves, accounted)                  # leaves not accounted for
[1] 500119

Similarly, to iterate over three or more lists, we use pmap_*(). The only difference is that all the lists are passed to pmap together, in one list. This can be better understood with the illustration used by Hadley Wickham in his book. See Figure 7.3.

For example, a data frame is a list of columns, so pmap() over a data frame takes one row at a time, with the column names matching the names of the function’s arguments.

bills <- data.frame(qty = c(10, 25, 40), rate = c(150, 80, 12.5), gst = c(18, 5, 18))
pmap_dbl(bills, \(qty, rate, gst) qty * rate * (1 + gst / 100))
[1] 1770 2100  590

Here, plain vector arithmetic, qty * rate * (1 + gst / 100), would have done the same. pmap() is needed when the function works on only one value at a time, like seq() above, or a function of our own with if.

7.5.3 Other useful purrr functions

  • walk(), walk2() and iwalk() work like map(), but for functions called for their side effects, like saving files or drawing plots, rather than for a result. We use iwalk() to save one file per district in Chapter 12.
  • list_rbind() binds a list of data frames into one, as when reading many files with map(). Its argument names_to adds a column with the names of the list elements, like the file each row came from. We use it in the audit use case below.
  • keep() and discard() keep or drop the elements of a list which meet a condition, like keep(claims, \(x) any(x > 100000)).
  • imap() passes each element along with its name, or position, as a second argument.
TipAudit tip

Whenever you find yourself running the same analysis on several files, districts, years or schemes, put them in a list and map() over it. One function, tested once, then runs on all of them alike. That is both quicker and more reliable than copying and editing code for each, where one small slip can go unnoticed.

7.6 Audit use case, the March rush in each office

A rush of expenditure in the last month of the year is a classic audit concern. Money spent in a hurry, to avoid its lapse, is often spent badly. The General Financial Rules, 2017 (Rule 62) treat such a rush as a breach of financial propriety. Government instructions also ask departments to keep spending in March within 15% of the budget, and in the last quarter within 33%. We have no budget figures here. So we use each office’s actual spending for the year as a rough yardstick instead.

Let us check every office in the same way. We split the vouchers into a list, one data frame per office. We write one function which checks one office. We test it on one office, and then map() it over all four.

office_list <- split(vouchers, vouchers$office)

march_check <- function(d) {
  in_march <- format(d$voucher_date, "%Y-%m") == "2025-03"
  in_q4    <- d$voucher_date >= as.Date("2025-01-01")
  data.frame(vouchers   = nrow(d),
             total_lakh = round(sum(d$amount) / 1e5, 2),
             q4_pct     = round(100 * sum(d$amount[in_q4]) / sum(d$amount), 1),
             march_pct  = round(100 * sum(d$amount[in_march]) / sum(d$amount), 1))
}

# Test on one office first
march_check(office_list$Pune)
  vouchers total_lakh q4_pct march_pct
1       31      30.35   27.6        16

The function works on one office. Now let us run it on all of them, and bind the results into one table with list_rbind(). Its argument names_to adds the name of each office as a column.

march_result <- office_list |>
  map(march_check) |>
  list_rbind(names_to = "office")
march_result
    office vouchers total_lakh q4_pct march_pct
1 Kolhapur       51      57.52   24.4      13.6
2   Nagpur       43      74.21   54.6      52.2
3   Nashik       42      38.16   21.6       3.7
4     Pune       31      30.35   27.6      16.0

Let us keep the offices which cross either yardstick.

subset(march_result, q4_pct > 33 | march_pct > 15)
  office vouchers total_lakh q4_pct march_pct
2 Nagpur       43      74.21   54.6      52.2
4   Pune       31      30.35   27.6      16.0

Nagpur stands out. It spent 52.2% of its year’s money in March, and 54.6% in the last quarter. Pune is also above the March yardstick, but only just, at 16%. That may be no more than the normal ups and downs of payments.

The auditor would next look at the Nagpur vouchers of March. Were the goods received, and the works done, before payment? Were any payments made in advance, only to avoid the lapse of funds? The March vouchers, with these questions, go into the working papers.

Note that the same function ran on every office alike. Had there been forty offices, the code would not have changed at all.

7.7 A suggested workflow

  1. Spot the repetition. Notice when the same work is done on several files, districts, years or schemes.
  2. Put the pieces in a list. Keep one data frame, or one vector, for each item. Use split() to break one table into groups if needed.
  3. Write and test one function. Make it work correctly on a single item first. A short anonymous function written with \(x) is enough for simple jobs.
  4. Map it over the list. Use map(), or lapply(), to run the same function on every item alike.
  5. Ask for the type of output you expect. Use map_dbl(), map_int() or vapply(), so that a surprise result stops with an error. Be careful with apply() on data frames that have text columns.
  6. Pair items with their own limits. Use map2() or pmap() when each item has its own limit or rate, like scheme-wise claim limits.
  7. Combine or save the results. Bind a list of data frames with list_rbind(), and use walk() or iwalk() to save one file for each item.
ImportantRemember

Test the function on one item before mapping it over all. Ask for the output type you expect, so that an odd result stops the code instead of passing silently. One tested function is safer than many copies of edited code.
