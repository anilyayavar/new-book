18  Working with Strings in stringr

In earlier chapters we covered the essential tools for reading, cleaning and reshaping data. Text is a little different. It is usually unstructured, and the same thing can be written in many ways. Yet audit data is full of text. Names of vendors and beneficiaries, addresses, narrations of vouchers, remarks, descriptions of goods. Before we can match, count or analyse such data, we must clean and standardise it. String manipulation is the toolkit for this.

In the chapter on functions, we saw some functions of base R for strings. The package stringr, part of tidyverse, has a consistent set of functions designed to make working with strings as easy as possible. All of them start with str_, take the string as their first argument, and work well with the pipe. We will learn the most useful of them in this chapter, and apply them to audit problems at the end.

First of all, let us load it. We will often use the function str_view(), which shows the underlying content of a string, and highlights the matches of a pattern between < and >. It is very useful while learning and checking, though rarely needed in final code.

library(tidyverse)   # loads stringr, along with dplyr and others

Let us also create a few example strings.

line1 <- "I'm gonna make him an offer he can't refuse."
line2 <- "Carpe diem.\nSeize the day, boys."
line3 <- "You've got to ask yourself one question: \"Do I feel lucky?\""

18.1 Printing strings the way we want

Let us try printing the above strings.

ex_lines <- c(line1, line2, line3)
print(ex_lines)
[1] "I'm gonna make him an offer he can't refuse."                 
[2] "Carpe diem.\nSeize the day, boys."                            
[3] "You've got to ask yourself one question: \"Do I feel lucky?\""

Not pretty! print() shows the strings as R stores them, with the escape characters, like \n for a new line and \" for a quote. In an earlier chapter we learnt the function cat(), which prints the content itself. So let us use that.

cat(line1, line2, line3)
I'm gonna make him an offer he can't refuse. Carpe diem.
Seize the day, boys. You've got to ask yourself one question: "Do I feel lucky?"

Prettier! But there is still a problem. The strings run into each other. cat() has a sep argument, which is placed between the strings.

cat(line1, line2, line3, sep = "\n")
I'm gonna make him an offer he can't refuse.
Carpe diem.
Seize the day, boys.
You've got to ask yourself one question: "Do I feel lucky?"

Base R has another function, writeLines(), designed especially to print strings the way we usually want them. cat(), on the other hand, is a general purpose function for joining and printing any objects.

writeLines(ex_lines)
I'm gonna make him an offer he can't refuse.
Carpe diem.
Seize the day, boys.
You've got to ask yourself one question: "Do I feel lucky?"
# Let's also print some Unicode and special characters.
writeLines("नमस्ते दुनिया")
नमस्ते दुनिया
writeLines("He owes me ₹ 15 lakh.")
He owes me ₹ 15 lakh.

In this context, let us also see str_view() from stringr, which we will use in the coming sections.

str_view(ex_lines)
[1] │ I'm gonna make him an offer he can't refuse.
[2] │ Carpe diem.
    │ Seize the day, boys.
[3] │ You've got to ask yourself one question: "Do I feel lucky?"

18.2 Unicode

Every character, in every script, has a number in the Unicode standard. In R, we can write a character by its number. \u is followed by up to four hexadecimal digits, as for the Devanagari letters and the rupee sign ₹ above. \U is followed by up to eight, which is needed for characters with bigger numbers, like these emoticons.

writeLines("\U1f600")
😀
writeLines("\U1f634")
😴

18.3 Cleaning whitespaces

We often meet strings with extra spaces at either end. They are invisible, but they make two strings unequal. See this comparison.

"anil goyal" == "anil goyal "
[1] FALSE

We may also meet extra spaces between words, which should be separated by a single space. stringr provides two functions for this.

  • str_trim(string, side = c("both", "left", "right")) removes spaces from both ends, or only the start or end, of the string. both is the default.
  • str_squish(string) removes the spaces at both ends and replaces every run of spaces inside the string with a single space.

Let us compare the two functions on names with extra spaces.

str_squish("anil     goyal ")
[1] "anil goyal"
str_trim("anil    goyal  ")
[1] "anil    goyal"

str_trim() has left the inner spaces as they were. For cleaning names and addresses before matching, str_squish() is nearly always the one we want.

18.4 String concatenation with str_c()

We have already seen two functions, paste() and paste0(), from base R. stringr has the function str_c() (c is short for concatenation) for the same purpose. But there are a couple of differences.

  1. The default sep is "", as in paste0(), as opposed to " " in paste().
  2. paste() turns missing values into the string "NA", whereas str_c() propagates missing values. Combining any string with a missing value gives a missing value.
company <- c("Microsoft", "Salesforce", NA)
product <- c("Excel", "Tableau", "R")
paste(company, product)
[1] "Microsoft Excel"    "Salesforce Tableau" "NA R"              
str_c(company, product, sep = " ")
[1] "Microsoft Excel"    "Salesforce Tableau" NA

The second behaviour is safer. A vendor code like "NA-Excel" can easily pass unnoticed through later steps, while an NA will be noticed.

str_c() returns a vector of the same length as its inputs, which makes it useful inside mutate(). To flatten a vector of strings into one string, we use the collapse argument of paste(), or better, str_flatten() from stringr. This is useful inside summarise(). It also has an argument last, for the separator before the last piece.

fruits <- c("apple", "banana", "pineapple")

str_flatten(fruits, collapse = ", ")
[1] "apple, banana, pineapple"
str_flatten(fruits, collapse = ", ", last = " and ")
[1] "apple, banana and pineapple"

There is a special variant str_flatten_comma(), where a comma is the default collapse argument, so we have to type a little less.

str_flatten_comma(fruits)
[1] "apple, banana, pineapple"

In this context, let us also see str_glue(), which gives an elegant way to insert values into a string, by writing their names inside {}.

# Note that output will be of same length as given variable/string vector.
str_glue("I like {fruits}")
I like apple
I like banana
I like pineapple
my_fruits <- str_flatten_comma(fruits, last = " and ")
str_glue("I like {my_fruits} in fruits.")
I like apple, banana and pineapple in fruits.

str_glue() is very handy for writing standard sentences in audit reports, from the results of an analysis, like str_glue("{n_cases} payments worth Rs {amount} lakh were made twice.").

18.5 String length with str_length()

To count the number of characters in a string, base R has nchar(). str_length() does the same.

str_length(ex_lines)
[1] 44 32 59

But it handles factors better than nchar().

# nchar(unique(iris$Species))
# Returns an error

# This will work
str_length(unique(iris$Species))
[1]  6 10  9

String length is a quick validity check in audit. A PAN must have 10 characters, an IFSC 11, and a mobile number 10 digits.

18.6 String extraction with str_sub()

str_sub() extracts parts of strings by position. Its first argument is a vector of strings. The other arguments, start and end, give the positions of the first and last characters of the piece to extract.

# Extracting first two characters
str_sub(fruits, 1, 2)
[1] "ap" "ba" "pi"

It works like substr() of base R. But unlike substr(), it accepts negative positions, which count backwards from the end of the string.

## Note the difference
substr(fruits, -2, -1)
[1] "" "" ""
str_sub(fruits, -2, -1)
[1] "le" "na" "le"

And it does not fail if a string is shorter than the positions given.

str_sub(fruits, 5, 6)
[1] "e"  "na" "ap"
str_sub(fruits, -6, -5)
[1] "a"  "ba" "ea"

Fixed positions carry meaning in many Indian codes. The first two characters of a GSTIN are the State code, the first four of an IFSC are the bank, and the last four digits of an account number are often all that may be shown. str_sub() takes them out.

str_sub("27AAPFU0939F1ZV", 1, 2)    # State code of a GSTIN
[1] "27"
str_sub("SBIN0001234", 1, 4)        # Bank code of an IFSC
[1] "SBIN"

18.7 String matching based on regex with str_detect(), str_subset() and str_count()

Let us search for "apple" in all three fruits strings.

str_view(fruits, "apple", match = NA)
[1] │ <apple>
[2] │ banana
[3] │ pine<apple>

There are three functions in stringr for this job.

  1. str_detect() works like grepl(), and returns a logical vector.
  2. str_subset() works like grep() with value = TRUE, and returns the matching strings.
  3. str_count() returns the number of matches in each string.
str_detect(fruits, "apple")
[1]  TRUE FALSE  TRUE
str_subset(fruits, "apple")
[1] "apple"     "pineapple"
str_count(fruits, "apple")
[1] 1 0 1
# Let's count character "a" in each of `fruits`
str_count(fruits, "a")
[1] 1 3 1

Two convenient relatives are str_starts() and str_ends(), which check only the beginning or the end of the strings.

str_starts(fruits, "pine")
[1] FALSE FALSE  TRUE
str_ends(fruits, "apple")
[1]  TRUE FALSE  TRUE

The patterns used in these functions are regular expressions, which we will learn in detail in the next chapter (Chapter 19).

Many auditors know the LIKE operator of SQL, where % stands for any number of characters and _ for exactly one character. stringr has the same, in str_like(). From stringr version 1.6, str_like() is case sensitive, exactly as SQL’s LIKE, and a new function str_ilike() ignores case.

firms <- c("Kumar Traders", "KUMAR TRADERS", "Sharma & Co")
str_like(firms, "%Traders%")
[1]  TRUE FALSE FALSE
str_ilike(firms, "%traders%")
[1]  TRUE  TRUE FALSE
# Invoice numbers of exactly four digits after INV-
str_like(c("INV-2231", "INV-22", "PO-2231"), "INV-____")
[1]  TRUE FALSE FALSE

18.8 Changing case in stringr

There are four functions in stringr to change the case of strings.

  1. str_to_lower() converts the string to lower case.
  2. str_to_upper() converts the string to UPPER CASE.
  3. str_to_title() converts the string to Title Case, where the first letter of every word is in upper case.
  4. str_to_sentence() converts to sentence case, where only the first letter of the string is capitalised.

Let us try each of them on the same string.

# lower case
str_view(str_to_lower(ex_lines))
[1] │ i'm gonna make him an offer he can't refuse.
[2] │ carpe diem.
    │ seize the day, boys.
[3] │ you've got to ask yourself one question: "do i feel lucky?"
# UPPER CASE
str_view(str_to_upper(ex_lines))
[1] │ I'M GONNA MAKE HIM AN OFFER HE CAN'T REFUSE.
[2] │ CARPE DIEM.
    │ SEIZE THE DAY, BOYS.
[3] │ YOU'VE GOT TO ASK YOURSELF ONE QUESTION: "DO I FEEL LUCKY?"
# Title Case
str_view(str_to_title(ex_lines))
[1] │ I'm Gonna Make Him An Offer He Can't Refuse.
[2] │ Carpe Diem.
    │ Seize The Day, Boys.
[3] │ You've Got To Ask Yourself One Question: "Do I Feel Lucky?"
# Sentence case
str_view(str_to_sentence(ex_lines))
[1] │ I'm gonna make him an offer he can't refuse.
[2] │ Carpe diem.
    │ Seize the day, boys.
[3] │ You've got to ask yourself one question: "do i feel lucky?"

Notice that str_to_sentence() turns every other letter into lower case, even the I in “Do I feel lucky?”.

TipAudit tip

Title and sentence case are fine for display, but for matching, always convert both sides to the same case, usually upper or lower.

18.9 Controlling matching behaviour with modifier functions in stringr

By default, the pattern in a stringr function is a regular expression. We can change how the pattern is treated by wrapping it in a modifier function.

  1. fixed() treats the pattern as plain text, character by character. Special characters like . lose their special meaning. It is also faster. It has an argument ignore_case.
  2. regex() is the default. Wrapping a pattern in it lets us set options, like ignore_case, which we will use in the next chapter.
  3. coll() compares text using the rules of a human language. It matters for scripts and accented letters, where the same letter can be stored in more than one way.

See these examples.

ex_str <- "This is an example string."
str_view(ex_str, "t")
[1] │ This is an example s<t>ring.
str_view(ex_str, fixed("."))
[1] │ This is an example string<.>
str_view(ex_str, regex("."))
[1] │ <T><h><i><s>< ><i><s>< ><a><n>< ><e><x><a><m><p><l><e>< ><s><t><r><i><n><g><.>
str_view(ex_str, regex("\\b.{2}\\b"))
[1] │ This <is> <an> example string.

fixed(".") matched only the full stop. As a regex, . means “any character”, so it matched every character. The last pattern matched two-letter words.

  1. One more modifier, boundary(), matches the boundaries between characters, lines, sentences or words. Its argument type takes one of "character", "line_break", "sentence" or "word".
str_view(ex_str, boundary("word"))
[1] │ <This> <is> <an> <example> <string>.
str_view(ex_lines, boundary("sentence"))
[1] │ <I'm gonna make him an offer he can't refuse.>
[2] │ <Carpe diem.
    │ ><Seize the day, boys.>
[3] │ <You've got to ask yourself one question: "Do I feel lucky?">

18.10 Extracting text from strings

We learnt above that str_subset() returns the strings in which the pattern is found. But often we want the matching text itself. For this, stringr has str_extract() and str_extract_all(). Let us extract PAN numbers from some text.

ex_text <- c("My PAN number is TEMPZ9999Z.",
             "He has mentioned TEMP9999Z as his PAN number, incorrectly.",
             "Is your PAN ABCTY1234D?")
# Let's define simple regex for PAN
pan <- "[A-Z]{5}[0-9]{4}[A-Z]"
# str_subset will return strings which contain PAN numbers
str_subset(ex_text, pattern = regex(pan))
[1] "My PAN number is TEMPZ9999Z." "Is your PAN ABCTY1234D?"     
# str_extract will however, extract those.
str_extract(ex_text, pattern = regex(pan))
[1] "TEMPZ9999Z" NA           "ABCTY1234D"

The second string has a PAN with only four letters at the start, so nothing was extracted. str_extract() returns the first match in each string. Its variant str_extract_all() returns all the matches, in a list.

text_2 <- str_flatten(ex_text, collapse = "\n")
str_extract(text_2, regex(pan))
[1] "TEMPZ9999Z"
str_extract_all(text_2, regex(pan))
[[1]]
[1] "TEMPZ9999Z" "ABCTY1234D"

str_extract_all() has an argument simplify. If TRUE, the output is a matrix instead of a list.

str_extract_all(text_2, regex(pan), simplify = TRUE)
     [,1]         [,2]        
[1,] "TEMPZ9999Z" "ABCTY1234D"

And to find how many PAN numbers are there in text_2,

str_count(text_2, regex(pan))
[1] 2

18.11 Splitting strings

str_split() splits strings into pieces, at a pattern. Since each string may give a different number of pieces, the output is a list.

Let us split each string into words.

str_split(ex_text, boundary("word"))
[[1]]
[1] "My"         "PAN"        "number"     "is"         "TEMPZ9999Z"

[[2]]
[1] "He"          "has"         "mentioned"   "TEMP9999Z"   "as"         
[6] "his"         "PAN"         "number"      "incorrectly"

[[3]]
[1] "Is"         "your"       "PAN"        "ABCTY1234D"

It has an argument n, the maximum number of pieces to return. The default is Inf. The last piece then holds the rest of the string, unsplit.

# Split each string into at most two pieces
str_split(ex_text, boundary("word"), n = 2)
[[1]]
[1] "My"                        "PAN number is TEMPZ9999Z."

[[2]]
[1] "He"                                                     
[2] "has mentioned TEMP9999Z as his PAN number, incorrectly."

[[3]]
[1] "Is"                   "your PAN ABCTY1234D?"

str_split() has three useful variants. str_split_fixed() splits each string into a fixed number of pieces, and returns a character matrix. Here n is required.

str_split_fixed(ex_text, boundary("word"), n = 3)
     [,1] [,2]   [,3]                                                 
[1,] "My" "PAN"  "number is TEMPZ9999Z."                              
[2,] "He" "has"  "mentioned TEMP9999Z as his PAN number, incorrectly."
[3,] "Is" "your" "PAN ABCTY1234D?"

str_split_1() takes a single string, and returns its pieces as a simple character vector.

# Note that vector with one element should be passed.
str_split_1(ex_text[1], boundary("word"))
[1] "My"         "PAN"        "number"     "is"         "TEMPZ9999Z"

str_split_i() splits each string and returns only the ith piece of each. This is very handy for fields separated by a fixed character, as we will see in the audit use cases.

str_split_i(ex_text, boundary("word"), i = 1)
[1] "My" "He" "Is"

18.12 Replacing values with str_replace(), str_replace_all()

To replace the matched text with something else, we use str_replace(), which replaces the first match, or str_replace_all(), which replaces all matches. They need one more argument, replacement.

# Example Task: mask all PAN numbers from `text_2`
# Let's view the string
str_view(text_2)
[1] │ My PAN number is TEMPZ9999Z.
    │ He has mentioned TEMP9999Z as his PAN number, incorrectly.
    │ Is your PAN ABCTY1234D?
# Replace first match only
str_replace(text_2, regex(pan), replacement = "XXXXX0000X") |>
  str_view()
[1] │ My PAN number is XXXXX0000X.
    │ He has mentioned TEMP9999Z as his PAN number, incorrectly.
    │ Is your PAN ABCTY1234D?
# Replace all matches
str_replace_all(text_2, regex(pan), replacement = "XXXXX0000X") |>
  str_view()
[1] │ My PAN number is XXXXX0000X.
    │ He has mentioned TEMP9999Z as his PAN number, incorrectly.
    │ Is your PAN XXXXX0000X?
TipAudit tip

PAN, Aadhaar and bank account numbers are personal data. Mask them in any output that goes outside the audit team, like a draft paragraph or an annexure. Keep the full values only in the secured working papers.

To make several replacements at once, we can give vectors of the same length for pattern and replacement. Let us see an example.

# Create a new string vector
fruits <- c("one apple",
            "two bananas",
            "three pineapples")
# See what's there in `fruits`
str_view(fruits)
[1] │ one apple
[2] │ two bananas
[3] │ three pineapples
# Let's replace each number word to numeral
str_replace_all(
  fruits,
  pattern = c("one", "two", "three"),
  replacement = c("1", "2", "3")
)
[1] "1 apple"      "2 bananas"    "3 pineapples"

Here the first pattern is applied to the first string, the second to the second, and so on. To apply all the replacements to every string, we give a named vector c(pattern1 = replacement1, ...) as the pattern.

str_replace_all(
  fruits,
  pattern = c(one = "1", two = "2", three = "3")
)
[1] "1 apple"      "2 bananas"    "3 pineapples"

Note: In a named vector, the names need not be quoted, unless they contain spaces or special characters. This is the most convenient way to apply a list of standard replacements, as we will do while cleaning vendor names.

Back-references. In replacement, \\1, \\2 and so on stand for the text matched by the first, second, and later groups in parentheses in the pattern. We will learn groups in Chapter 19.

# If any consonant is repeated, make it single
str_replace_all(fruits,
                pattern = regex("([^aeiou])\\1", ignore_case = TRUE),
                replacement = "\\1")
[1] "one aple"        "two bananas"     "three pineaples"

We may also give a function as the replacement. It is called for each match, and its result replaces the match.

# Change case of all PAN numbers which are in lower case.
text_3 <- str_to_lower(text_2)
# Let's view the string
str_view(text_3)
[1] │ my pan number is tempz9999z.
    │ he has mentioned temp9999z as his pan number, incorrectly.
    │ is your pan abcty1234d?
# Change case of all lower case PAN numbers
str_replace_all(text_3,
                pattern = regex(pan, ignore_case = TRUE),
                replacement = str_to_upper) |>
  str_view()
[1] │ my pan number is TEMPZ9999Z.
    │ he has mentioned temp9999z as his pan number, incorrectly.
    │ is your pan ABCTY1234D?

Only the PAN numbers have been changed to upper case. The rest of the text is still in lower case.

18.13 Removing text/pattern using str_remove and str_remove_all

Removing a pattern is the same as replacing it with the empty text "". In the example below, we remove the four digits from the middle of each valid PAN in the text. The pattern uses look-arounds, which we will learn in Chapter 19. It matches four digits only if they come after five letters and before one letter.

str_remove_all(ex_text,
               pattern = regex("(?<=[A-Z]{5})(\\d{4})(?=[A-Z])", ignore_case = TRUE)) |>
  str_view()
[1] │ My PAN number is TEMPZZ.
[2] │ He has mentioned TEMP9999Z as his PAN number, incorrectly.
[3] │ Is your PAN ABCTYD?

18.14 Formatting numbers with format and formatC

Numbers often have to be shown in a particular way, with a currency symbol, thousand separators, or in fixed rather than scientific notation. The base R function format() does this. Its argument scientific controls whether the numbers are shown in fixed (scientific = FALSE) or scientific (scientific = TRUE) notation. The argument digits sets the minimum number of significant digits.

Each number is then formatted with the same number of decimal places, enough to show the significant digits of the smallest number. So the number of decimal places we get depends on all the values being formatted.

# Some example numbers
numbers <- c(0.00123, 123, 1.2356)
# Default
format(numbers, digits = 1) |>
  writeLines()
1e-03
1e+02
1e+00
# Fixed format
format(numbers, digits = 1, scientific = FALSE) |>
  writeLines()
  0.001
123.000
  1.236

In the output above, the smallest number is 0.00123. To show it with one significant digit, three decimal places are needed. So all the numbers get three decimal places.

Notice also that the output is aligned at the decimal point, by adding spaces at the start. To stop this, we set trim = TRUE.

format(numbers,
       digits = 1,
       scientific = FALSE,
       trim = TRUE) |>
  writeLines()
0.001
123.000
1.236

The function formatC() gives another way to format numbers, using the style of the C language. Instead of scientific, it has an argument format, which takes a code. The most useful are

  • "f" for fixed format. Here, digits is the number of digits after the decimal point. This is more predictable than format(), because the number of decimal places does not depend on the other values.
  • "e" for scientific notation. Here, digits is the number of digits after the decimal point of the mantissa.
  • "g" for fixed, unless scientific saves space. Here, digits is the number of significant digits.

formatC() also formats each number on its own, so we always get the same output for a number, whatever the other numbers in the vector.

formatC(numbers,
        format = "f",
        digits = 2) |>

        format = "g",
        digits = 2) |>
  writeLines()
0.0012
1.2e+02
1.2

18.14.1 Indian style of numbers

All the above functions put a comma every three digits, as in 1,234,567. In India, we write the same number as 12,34,567. After the last three digits, the commas come every two digits. None of the common functions does this, but a short regular expression does. We will understand the pattern fully after Chapter 19. For now, it is enough to know that it puts a comma after any digit which is followed by some pairs of digits and then the last three digits.

format_inr <- function(x, digits = 0) {
  s <- formatC(abs(x), format = "f", digits = digits)
  whole   <- str_extract(s, "^\\d+")
  decimal <- str_extract(s, "\\.\\d+$")
  # comma after a digit followed by pairs of digits and then the last three digits
  whole <- str_replace_all(whole, "(\\d)(?=(\\d{2})+\\d{3}$)", "\\1,")
  # comma before the last three digits
  whole <- str_replace(whole, "(\\d)(?=\\d{3}$)", "\\1,")
  str_c(if_else(x < 0, "-", ""), whole, coalesce(decimal, ""))
}

format_inr(c(999, 12345, 1234567, 123456789, -5432100.5), digits = 0)
[1] "999"          "12,345"       "12,34,567"    "12,34,56,789" "-54,32,101"

In audit reports, large amounts are usually shown in lakh or crore. That only needs a division.

amounts <- c(4567890, 123456789, 98765)
str_glue("Rs {format_inr(amounts / 1e5, digits = 2)} lakh")

str_glue("Rs {format_inr(amounts / 1e7, digits = 2)} crore")

18.15 Padding strings

We removed extra spaces with str_trim(). Sometimes we need the opposite, to add spaces or some other character to the left, right or both sides of strings, so that all of them have the same length. str_pad() does this. Its syntax is

str_pad(
  string,
  width,
  side = c("left", "right", "both"),
  pad = " ",
  use_width = TRUE
)

Let us pad the same name on the left, on the right and on both sides.

str_view(
  c(str_pad("anil", 30, "left"),
  str_pad("anil", 30, "right"),
  str_pad("anil", 30, "both"))
)
[1] │                           anil
[2] │ anil                          
[3] │              anil

Padding with zeros is very useful for codes and account numbers, as we will see in the audit use cases.

str_pad(c("7", "45", "123"), width = 5, pad = "0")
[1] "00007" "00045" "00123"

18.16 Sorting strings

To sort strings, stringr has three functions.

  • str_sort() returns the sorted vector.
  • str_order() returns the positions of the strings in sorted order, so that x[str_order(x)] is the same as str_sort(x).
  • str_rank() returns the rank of each string.

All of them have an argument numeric. If set to TRUE, digits are sorted as numbers, instead of as text. The following example makes this clear.

str_view(fruits)
[1] │ one apple
[2] │ two bananas
[3] │ three pineapples
# Let's sort these alphabetically
str_sort(fruits)
[1] "one apple"        "three pineapples" "two bananas"     
# Let's find the alphabetic order
str_order(fruits)
[1] 1 3 2
# Amounts stored as text
ex_text <- c("₹100", "₹200", "₹1000", "₹500", "₹5000", "₹10000")

# default sorting
str_sort(ex_text)
[1] "₹100"   "₹1000"  "₹10000" "₹200"   "₹500"   "₹5000" 
# Order
str_order(ex_text)
[1] 1 3 6 2 4 5
# Rank
str_rank(ex_text)
[1] 1 4 2 5 6 3
# sorting based on numbers
str_sort(ex_text, numeric = TRUE)
[1] "₹100"   "₹200"   "₹500"   "₹1000"  "₹5000"  "₹10000"

As text, "₹1000" comes before "₹200", because the character 1 comes before 2. With numeric = TRUE, the amounts are sorted by value. The same problem arises with file names like bill_2, bill_10 and voucher numbers like PV-9, PV-10.

18.17 Audit use case 1, standardising names before matching

Duplicate checks (Chapter 32) and string similarity (Chapter 33) work much better on clean names. The same vendor can be written as “M/s Sharma Traders Pvt. Ltd.”, “SHARMA TRADERS PRIVATE LIMITED” and “Sharma Traders (P) Ltd”. Exact matching treats these as three vendors. Let us build a small cleaning function, using what we have learnt.

vendors <- tibble(
  vendor_id = sprintf("V%02d", 1:8),
  name = c("M/s Sharma Traders Pvt. Ltd.", "SHARMA TRADERS PRIVATE LIMITED",
           "Sharma  Traders (P) Ltd", "Shri Ganesh Enterprises",
           "Sri Ganesh Enterprises ", "M/S. GUPTA & SONS",
           "Gupta and Sons", "Kaveri Infra Projects Ltd.")
)

clean_name <- function(x) {
  x |>
    str_to_upper() |>
    # common forms of legal suffixes and honorifics, written one way
    str_replace_all(c("\\bPRIVATE\\b"  = "PVT",
                      "\\(P\\)"        = "PVT",
                      "\\bLIMITED\\b"  = "LTD",
                      "&"              = " AND ",
                      "\\bSRI\\b"      = "SHRI")) |>
    # remove M/s at the start
    str_remove("^M\\s*/\\s*S\\.?\\s*") |>
    # punctuation to space, then squish spaces
    str_replace_all("[[:punct:]]", " ") |>
    str_squish()
}

vendors |>
  mutate(clean = clean_name(name))
# A tibble: 8 × 3
  vendor_id name                             clean                    
  <chr>     <chr>                            <chr>                    
1 V01       "M/s Sharma Traders Pvt. Ltd."   SHARMA TRADERS PVT LTD   
2 V02       "SHARMA TRADERS PRIVATE LIMITED" SHARMA TRADERS PVT LTD   
3 V03       "Sharma  Traders (P) Ltd"        SHARMA TRADERS PVT LTD   
4 V04       "Shri Ganesh Enterprises"        SHRI GANESH ENTERPRISES  
5 V05       "Sri Ganesh Enterprises "        SHRI GANESH ENTERPRISES  
6 V06       "M/S. GUPTA & SONS"              GUPTA AND SONS           
7 V07       "Gupta and Sons"                 GUPTA AND SONS           
8 V08       "Kaveri Infra Projects Ltd."     KAVERI INFRA PROJECTS LTD

The 8 names have become 4 distinct clean names. The three forms of Sharma Traders are now identical, and so are the Ganesh and Gupta pairs. Now an exact duplicate check, or a similarity check, can find them.

TipAudit tip

Keep the original name, and add the clean name as a new column, as we did. Report findings with the original names, so that the auditee recognises the records. Build the list of replacements from your own data. Look at the most frequent words with str_split() and count(), and add their variants to the list.

18.18 Audit use case 2, reading bank statement narrations

Bank statements describe each transaction in a single narration column, with fields separated by a character like /. For example, a NEFT payment may read NEFT/ICIC0001234/SHARMA TRADERS/INV-2231. To analyse the payments, we need these fields in separate columns. Amounts written in text also need converting into numbers.

statement <- tibble(
  txn_date = as.Date(c("2024-06-03", "2024-06-03", "2024-06-05", "2024-06-07", "2024-06-09")),
  narration = c("NEFT/ICIC0001234/SHARMA TRADERS/INV-2231",
                "RTGS/HDFC0000456/KAVERI INFRA PROJECTS/RA BILL 4",
                "NEFT/SBIN0004567/SHARMA TRADERS/INV-2231",
                "CHQ 004512 CLEARED SELF",
                "NEFT/PUNB0123400/GUPTA AND SONS/INV-88"),
  amount_text = c("Rs. 1,25,000/-", "Rs 12,40,500.00", "Rs. 1,25,000/-", "Rs. 50,000/-", "INR 9,800")
)

str_split_i() takes out each field by its position. Only the narrations starting with NEFT or RTGS have this structure, so we take the first word of each narration as the mode, and split only those.

statement_parsed <- statement |>
  mutate(
    mode      = str_extract(narration, "^[A-Z]+"),     # the first word, like NEFT or CHQ
    is_eft    = mode %in% c("NEFT", "RTGS"),
    ifsc      = if_else(is_eft, str_split_i(narration, "/", 2), NA),
    party     = if_else(is_eft, str_split_i(narration, "/", 3), NA),
    reference = if_else(is_eft, str_split_i(narration, "/", 4), NA),
    cheque_no = str_extract(narration, "(?<=CHQ )\\d+"),
    # first remove the currency prefix, then everything except digits and the decimal point
    amount    = amount_text |>
                  str_remove("^(Rs\\.?|INR)\\s*") |>
                  str_remove_all("[^0-9.]") |>
                  as.numeric()
  )

statement_parsed |>
  select(txn_date, mode, ifsc, party, reference, cheque_no, amount) |>
  print(width = Inf)
# A tibble: 5 × 7
  txn_date   mode  ifsc        party                 reference cheque_no  amount
  <date>     <chr> <chr>       <chr>                 <chr>     <chr>       <dbl>
1 2024-06-03 NEFT  ICIC0001234 SHARMA TRADERS        INV-2231  <NA>       125000
2 2024-06-03 RTGS  HDFC0000456 KAVERI INFRA PROJECTS RA BILL 4 <NA>      1240500
3 2024-06-05 NEFT  SBIN0004567 SHARMA TRADERS        INV-2231  <NA>       125000
4 2024-06-07 CHQ   <NA>        <NA>                  <NA>      004512      50000
5 2024-06-09 NEFT  PUNB0123400 GUPTA AND SONS        INV-88    <NA>         9800

Notice the two steps in the amount. First we remove the currency prefix, Rs, Rs. or INR. Then we remove every character which is not a digit or a decimal point, which takes away the spaces, the commas and the /- at the end.

WarningCaution

The order matters. If we skipped the first step, the dot of Rs. would survive the second step, as it looks like a decimal point. "Rs. 1,25,000/-" would become ".125000", which R reads as 0.125! Always check a few converted amounts against the original text.

# The trap, without removing the prefix first
as.numeric(str_remove_all("Rs. 1,25,000/-", "[^0-9.]"))
[1] 0.125

Now the fields can be analysed like any other data. For example, the same party and reference paid twice is a possible duplicate payment. Here, the same invoice of Sharma Traders was paid twice, two days apart, and to accounts in two different bank branches (IFSC). A second account for the same payee makes it even more worth checking.

statement_parsed |>
  filter(is_eft) |>
  filter(n() > 1, .by = c(party, reference, amount)) |>
  select(txn_date, ifsc, party, reference, amount)
# A tibble: 2 × 5
  txn_date   ifsc        party          reference amount
  <date>     <chr>       <chr>          <chr>      <dbl>
1 2024-06-03 ICIC0001234 SHARMA TRADERS INV-2231  125000
2 2024-06-05 SBIN0004567 SHARMA TRADERS INV-2231  125000
WarningCaution

Bank narrations are not standard. Different banks, and even different branches, write them differently, and they are often cut short. Look at a sample of narrations of each kind before writing the patterns, and count how many rows each pattern could not parse. Those rows must be checked separately.

18.19 Audit use case 3, lost leading zeros

Codes like employee numbers, account numbers and PIN codes often start with zeros. When such data passes through a spreadsheet, the codes are often read as numbers, and the leading zeros are lost. Then "00123" in one table becomes "123" in another, and a join between the two silently fails.

payroll  <- tibble(emp_code = c("00123", "00456", "01789", "12001"),
                   salary   = c(52000, 61000, 48000, 75000))
# The same codes, after passing through a spreadsheet
bank_upload <- tibble(emp_code = c("123", "456", "1789", "12001"),
                      account  = c("XXXX4521", "XXXX8890", "XXXX1102", "XXXX7731"))

# A plain join matches only one employee
payroll |> inner_join(bank_upload, by = "emp_code")
# A tibble: 1 × 3
  emp_code salary account 
  <chr>     <dbl> <chr>   
1 12001     75000 XXXX7731

Only one of the four employees matched. Padding the codes back to their full length fixes the join.

bank_upload <- bank_upload |>
  mutate(emp_code = str_pad(emp_code, width = 5, pad = "0"))

payroll |> inner_join(bank_upload, by = "emp_code")
# A tibble: 4 × 3
  emp_code salary account 
  <chr>     <dbl> <chr>   
1 00123     52000 XXXX4521
2 00456     61000 XXXX8890
3 01789     48000 XXXX1102
4 12001     75000 XXXX7731
TipAudit tip

Before joining two tables, compare the length and format of the key columns with str_length() and count(). A key which has different lengths in two tables is a warning. While reading data, read code columns as text, for example with col_types = cols(emp_code = col_character()) in read_csv(), so that leading zeros are never lost in the first place.

18.20 A suggested workflow

  1. Look at the raw text first. View a sample with str_view(), and count the distinct values.
  2. Keep the original column and create cleaned columns next to it.
  3. Standardise case, spaces and punctuation with str_to_upper(), str_squish() and str_replace_all().
  4. Apply a list of standard replacements for abbreviations and honorifics, as a named vector.
  5. Split and extract fields with str_split_i(), str_sub() and str_extract().
  6. Convert text amounts and dates into numbers and dates, and check a sample by hand.
  7. Pad codes to a fixed length before joining tables.
  8. Count what could not be cleaned or parsed, and examine those rows separately.
ImportantRemember

Cleaning changes the data. Every replacement rule can merge two things that are really different, like two genuinely different firms with similar names. Keep the original values, apply cleaning rules you can explain, and verify the matches that matter before reporting them.
