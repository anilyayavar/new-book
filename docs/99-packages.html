Appendix C — R Packages Used in This Book

R comes with a large set of functions, called base R. Most of the work in this book also uses packages, collections of functions written by others and shared freely, mostly through CRAN, the Comprehensive R Archive Network. Section 5 explains how packages are installed and loaded. This appendix lists all the packages used in the book, with a single command to install them.

C.1 Packages by part

MASS, lattice and nnet, also used in the book, come with every installation of R and need no separate installation.

C.2 Installing all the packages

The following command installs every CRAN package used in the book. It needs an internet connection, and may take a while the first time. If your office network blocks downloads, see the note on installing packages on an office network in Section 5.

install.packages(c(
  "tidyverse", "conflicted", "readxl", "writexl", "openxlsx", "janitor",
  "pdftools", "tidyxl", "unpivotr", "data.table", "duckdb", "dbplyr",
  "scales", "ggrepel", "patchwork", "psych", "skimr", "GGally", "PerformanceAnalytics", "broom",
  "rebus", "stringdist", "phonics", "PGRdup",
  "validate", "pointblank", "benford.analysis", "bupaR", "processmapR", "edeaR", "processcheckR",
  "performance", "car", "moderndive", "rpart", "rpart.plot", "ranger", "cluster", "factoextra",
  "arules", "forecast", "timetk", "zoo", "outliers", "FNN", "dbscan", "isotree", "changepoint", "deaR",
  "tidytext", "SnowballC", "wordcloud",
  "igraph", "igraphdata", "ggraph", "visNetwork",
  "sf", "leaflet", "tidygeocoder",
  "gt", "quarto", "RColorBrewer", "colorspace", "palmerpenguins", "remotes"
))

Two packages are not on CRAN, and are installed from GitHub with the package remotes.

# Double Metaphone with full-length codes, by Atharv Tyagi
remotes::install_github("AtharvTyagi1805/cagmetaphone")
# Seasonal Hybrid ESD anomaly detection, by Twitter
remotes::install_github("twitter/AnomalyDetection")

The first of these, a full implementation of the Double Metaphone algorithm keeping phonetic codes of up to 32 characters, was developed by Atharv Tyagi during an internship under the author’s guidance. It is used in Chapter 33, Chapter 32 and Chapter 34.

TipKeeping an analysis reproducible

Packages are updated from time to time, and occasionally a function changes its behaviour. For an audit that must be reproducible, record the versions used, as shown in Section 7 with sessionInfo(). For larger projects, the package renv keeps a separate, fixed set of package versions for each project, so that an analysis written today runs the same way next year.
